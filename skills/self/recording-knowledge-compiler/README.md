# 录音知识编译器

将录音、视频及其配套课件、图片、制度原文和辅助文本，编译为可独立阅读、可追溯核查、可持续维护的知识文档。

它的目标不是把材料压缩成摘要，而是在清理口语噪声的同时，保全可证实的定义、条件、例外、数字、案例、问答和推理链。适合课程讲义、培训资料、岗位手册、制度解读和入职知识库等场景。

本仓库提供的是**技能定义与交付校验器**，不是独立的音视频转写命令行程序。需要在支持技能调用的 Codex/Claude 环境中使用；原始音视频的证据提取依赖同环境中的 `video-evidence-extraction` 技能。

## 能做什么

- 从录音或视频中提取并核查转写与时间对齐证据。
- 逐页整合 PDF/PPT、逐张整合截图或照片，以及辅助笔记、讲稿等文本材料。
- 按来源角色处理冲突：正式课件负责规范定义与参数，讲解录音补充推理、案例和现场修正。
- 生成一套可审计的 Markdown 交付物，其中最终稿可脱离原始材料独立阅读。
- 支持对既有讲义或手册做保守的增量更新，保留基线内容的去向和修改依据。
- 通过内置校验器检查文件齐全性、标题结构、覆盖账本与常见交付禁用项。

## 工作流

```mermaid
flowchart LR
    A[锁定交付范围] --> B[建立可核查证据]
    B --> C[建立来源覆盖账本]
    C --> D[协调冲突并编译五件套]
    D --> E[人工语义审计]
    E --> F[运行机械校验]
```

关键原则：先建立可核查证据和覆盖账本，再开始连续写作。若关键媒体无法验证、完整课件无法逐页检查，或存在未映射的实质内容，应输出 `INSUFFICIENT_DATA`，而不是把局部材料表述为完整课程。

## 输入材料

可组合使用下列材料；每个材料都应注明它在本次编译中的角色。

| 材料 | 主要用途 | 注意事项 |
| --- | --- | --- |
| 原始音频/视频 | 讲师解释、案例、问答、强调与现场修正 | 先生成并验证转写、时间对齐证据。 |
| 完整 PDF/PPT 或制度原文 | 正式标题、定义、表格、流程、参数 | 必须逐页检查。 |
| 课件照片/局部截图 | 清晰可见的局部文字、图表与层级 | 只能证明画面所覆盖区域，不能替代完整课件。 |
| 笔记、讲稿、已有转写 | 术语线索、缺失片段救援、交叉验证 | 未与主要材料核对前，不能升级为确定事实。 |
| 既有讲义/手册 | 增量更新的结构与已发布表达 | 默认保留；被新证据改变时必须记录去向。 |

## 输出：知识编译五件套

默认会在指定输出目录生成以下 UTF-8 Markdown 文件。用户指定命名时可覆盖默认名称。

| 文件 | 作用 |
| --- | --- |
| `01_术语与纠错表.md` | 记录有实质影响的术语归一、ASR 纠错、数字核对和版本修正。 |
| `02_完整书面稿.md` | 按原始讲授顺序整理的完整书面稿，用于与音视频反向核查。 |
| `03_知识点讲义.md` | 面向课程、培训或知识库的最终稿，按知识结构重组；与下一项二选一。 |
| `03_指导手册.md` | 面向流程、制度、岗位或入职场景的最终稿；与上一项二选一。 |
| `04_待回听确认项.md` | 仅记录交付时仍无法可靠解决、且确实需要回听或补充材料的问题。 |
| `05_内容覆盖表.md` | 覆盖账本：将每个材料单元映射到书面稿、最终稿或待确认项。 |

最终稿不得包含时间戳、源文件名、图片编号、内部证据路径、编辑待办或“详见课件”等依赖外部材料才能理解的表述。

交付目录必须恰有五个文件：前述四个固定文件，加上一种 `03` 最终稿。两种 `03` 文件同时存在时，校验器会要求通过 `--final` 明确指定。

## 使用方式

在支持技能调用的 Codex/Claude 环境中，提供录音（或视频）及所有配套材料，并说明：

- 目标读者与文档用途；
- 新建或增量更新；
- 哪些材料是完整正式课件、哪些是局部图片或辅助文本；
- 指定的权威来源、输出目录和最终稿名称。

示例提示词：

```text
使用 $recording-knowledge-compiler 将这段录音及配套资料编译为可独立使用的知识讲义。

读者：新入职的运营同学
模式：新建
权威材料：完整课件 PDF 与录音
输出目录：./output
最终稿：03_知识点讲义.md
```

对于包含原始音视频的任务，本技能会先调用 `video-evidence-extraction` 建立可验证的转写和关键帧证据。只有该技能给出的 `validation.json` 没有 `errors` 时，才使用其转写和帧；已有符合此条件的证据目录时会直接复用，避免重复转写。

## 增量更新

对已有讲义或手册补充新材料时，先完整读取基线，再为每个实质单元登记以下处理之一：`保留`、`补充`、`合并`、`替换`、`冲突`。

默认保持原有结构和措辞，仅在相关主题附近做最小跨度修改。任何删除都需要可核查的依据；无法判定的冲突应进入 `04_待回听确认项.md`，而不是静默改写。

## 校验交付包

校验器只读，不会修改交付文件。需要 Python 3.9 或更新版本，且不依赖第三方包。

```powershell
python .\scripts\validate_package.py <五件套目录>
```

可选参数：

```powershell
# 显式指定最终稿（适用于自定义名称或同时存在两类最终稿时）
python .\scripts\validate_package.py <五件套目录> --final <最终稿路径>

# 增量更新时额外检查基线与最终稿的保真风险
python .\scripts\validate_package.py <五件套目录> --baseline <基线文件路径>

# 输出 JSON，便于 CI 或其他程序处理
python .\scripts\validate_package.py <五件套目录> --json
```

退出码含义：

| 退出码 | 含义 |
| --- | --- |
| `0` | 通过：未发现结构或模式问题。 |
| `1` | 需人工复核：存在警告，但没有硬性失败。 |
| `2` | 硬性失败：例如缺少必需文件、文件为空或最终稿无法确定。 |

机械校验不能替代人工语义审计。交付前仍应按覆盖表抽查来源与正文之间的双向映射，确认定义、条件、数字、例外、案例和完整问答均已保留。

## 质量边界

“无损”是指不丢失能够由材料证实的语义和事实，不是保留逐字口癖，也不意味着在材料不完整时虚构完整性。若只收到截断录音、局部截图或无法辨读的关键页面，成品应明确标示已覆盖范围，并列出继续完成所需的最小材料。

此时应在交付报告中标记 `INSUFFICIENT_DATA`。它表示本轮不能作出“完整材料已全部覆盖”的声明，并不妨碍交付已验证范围内的中间成果。

详细约束请参阅 [输出契约](references/output-contract.md)、[质量门禁](references/quality-gates.md) 和 [来源协调规则](references/source-reconciliation.md)。
