# Recording Knowledge Compiler

把材料编译成可独立使用的文档。这里的“无损”指保全材料支持的语义、事实、条件、例外、数字、案例、问答和推理，以及主体、时点、适用范围与完成状态，不是保留逐字口癖。

## 1. 锁定交付契约

从用户要求和工作区确定：读者、文档用途、新建或增量模式、材料清单与编译区间、指定权威、输出目录与最终稿名称。按成品用途选择：理解概念与方法用 `03_知识点讲义.md`，执行任务用 `03_指导手册.md`，理解本次讨论并承接决定与工作用 `03_会议文档.md`。用户指定优先，混合材料按主要用途组织并保留其他实质内容。选择会议文档时读取 [references/meeting-document.md](references/meeting-document.md)。

完整性以用户确定的材料和区间为边界；范围记录进入编译包，正文保留影响使用的日期和适用条件。用户已排除的未录部分不构成待补材料或完整性缺口。

把能通过文件和环境检查确定的事实直接查明。只有缺失选择会实质改变成品时才询问用户。

完成条件：每项输入都有路径和角色，交付模式、最终稿类型与输出位置均已确定。

## 2. 建立可核查证据

输入含原始音频或视频时，调用 `$video-evidence-extraction` 完成预检、提取和验证。只有其 `validation.json` 没有 `errors` 才读取转写和帧；把 `warnings` 带入本技能的质量判断。已有合格证据目录时直接复用，不重复转写。

逐页查看 PDF/PPT，逐张查看图片；抽取文本和 OCR 只作定位线索。完整正式课件必须枚举到最后一页，局部照片必须逐张登记。用户提供的转写可作为本轮主要编译来源；其中附带的纪要、速览和自动总结只作导航。辅助笔记和讲稿先按待核材料处理。

完成条件：每个媒体输入已验证或明确不可用；每个页面、幻灯片、图片和辅助文本单元已登记、阅读或精确标记为不可读。

## 3. 建立覆盖账本

建立覆盖账本前，完整读取 [references/source-reconciliation.md](references/source-reconciliation.md)。先建立覆盖账本，再开始连续写作。

账本的每行对应一个可定位的材料单元，至少记录：来源单元、主题、关键事实/案例/问答/参数、置信度、冲突或缺口、`02` 落点、`03` 落点、处理状态。长录音按语义连续区间切分；课件和图片按页/张切分；辅助文本按段落或章节切分。

完成条件：每个已登记材料单元都映射到 `02`、`03` 或 `04`，不存在“后续再看”“已处理”之类无具体落点的占位行。

## 4. 对齐、纠错与增量合并

按来源角色而非机械投票协调信息。明确纠正可直接落入正文；未能解决的冲突保留各自说法和证据位置，进入 `04`。影响主体识别或责任关系的专名先用上下文和既有材料核对；仍无法确定且可由公开资料解决时，按任务授权查询官方来源，依据进入 `01`。其他外部检索限于用户要求扩展/核查，或关键冲突无法靠现有材料解决；区分外部事实与来源主张。

增量模式先完整阅读基线，把每个实质段落登记为“保留、补充、合并、替换、冲突”之一。默认保留结构和措辞，在相关主题附近做最小跨度修改。新增课件内容与对应知识点融合，不建立孤立的“课件补充”“图片补充”章节。删除项逐项说明依据。

完成条件：所有冲突都有决议或 `04` 记录；增量模式下每个基线实质单元都有去向，每项删除都有可核查理由。

## 5. 编译五件套

开始写作前完整读取 [references/output-contract.md](references/output-contract.md)，并严格生成其中定义的五个文件。

先写 `01` 和按原始顺序展开的 `02`，再依据覆盖账本将材料重组为 `03`，随后完成 `04` 和 `05`。`03` 补足材料支持的指代和必要上下文，直接呈现具体内容；概念、案例与问答按来源实际信息量展开。正文与原始来源对照验收，不能只依赖 `02` 的再加工。

完成条件：五个文件均非空；`02` 覆盖范围内全部实质内容；`03` 保留已确认的实质内容及其关系与状态；`04` 收口所有未决项；`05` 能反向追踪每个材料单元。

## 6. 运行质量门禁

完整读取 [references/quality-gates.md](references/quality-gates.md)，先人工执行语义审计，再运行机械校验：

```powershell
<python> <skill-dir>/scripts/validate_package.py <package-dir> [--final <path>] [--baseline <path>] [--json]
```

退出码：`0` 为通过，`1` 为需要人工复核，`2` 为硬性失败。机械通过只证明结构和禁用模式通过，不能证明语义完整。

完成条件：没有硬性失败；所有警告已人工处置或在交付说明中披露；覆盖账本中的实质内容与正文一致。

## 7. 交付或停止

范围内关键媒体验证失败、指定的完整课件未能逐页检查、关键材料不可读，或覆盖账本存在实质缺口时，使用 `INSUFFICIENT_DATA`，说明已完成范围、受影响结论，以及继续所需的最小材料或检查。可以保留不受影响的中间成果。

满足门禁时，报告五件套路径、最终稿类型、增量模式下的保留/修改范围，以及仍需人工关注的警告。
