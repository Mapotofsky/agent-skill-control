# 按需示例

仅在需要校准复杂提示词或区分运行环境时读取。示例展示决策原则，不是必须照搬的模板。

## 1. 简单请求保持简单

用户：“帮我写一个 prompt，把中文产品说明翻译成自然英文。”

```text
将下面的中文产品说明翻译成自然、准确的英文。保留产品名和技术术语；不要添加原文没有的信息。

原文：
[粘贴内容]
```

无需虚构角色、固定章节、示例或 XML。

## 2. 模糊但低风险：基于假设直接草拟

用户：“写一个让 AI 帮我改邮件的提示词。”

```text
请重写下面的邮件，使表达清楚、礼貌、自然，并保留原意和所有事实。默认受众为工作联系人，语气专业但不生硬。若原文存在决定含义的歧义，先指出最小歧义；否则直接给出重写版。

邮件原文：
[粘贴内容]
```

关键是把低风险默认值写成假设，而不是先追问长度、职位和格式。

## 3. 决定性歧义：只问最小问题

用户：“给 Codex 写个 prompt，把生产数据库迁移到新结构。”

先问：

> 这是只生成迁移方案并验证，还是获准连接并修改生产数据库？

授权范围会实质改变副作用和风险，不能自行假设。其他可从仓库或环境核实的信息不重复询问。

## 4. Codex 编程任务

```text
目标：修复用户登出后浏览器返回仍显示受保护页面的问题。

当前状态：复现路径和相关测试位于仓库现有认证模块；先检查现有实现与项目规则。

范围与授权：可编辑认证模块及直接相关测试，可运行本地非破坏性测试；不要改动无关路由、依赖或部署配置，不要执行外部发布。

成功标准：
- 登出后返回受保护页面会重定向到登录页；
- 现有认证行为保持通过；
- 添加或更新能复现该问题的测试。

完成实现与验证后停止。若修复必须改变公开会话语义，报告最小阻塞点并等待确认。
```

让 agent 自选调查与实现路径；路径不是验收标准时无需规定逐步过程。

## 5. 中央假设被纠正

原先假设：“数据源是静态 CSV。”用户纠正：“实际是可分页 API。”

应生成新的当前版本：

```text
目标：从可分页 API 拉取全部订单并生成每日汇总。

输入与边界：使用现有 API 客户端；遵守分页游标和速率限制；不得把单页结果视为全集。

成功标准：处理所有页面、去重订单 ID、记录不完整拉取，并用测试覆盖多页与中途失败。
```

不要保留围绕 CSV 的步骤，也不要在末尾追加一串旧方案 caveat。

## 6. OpenAI API：稳定契约与当轮输入分开

Developer 指令：

```text
把客服工单分类为 billing、technical 或 account。只能依据工单文本；无法判断时返回 needs_review。输出必须符合调用方提供的结构化 schema。
```

User 输入：

```text
工单：升级后仍显示旧套餐，但信用卡已按新套餐扣款。
```

长期分类规则属于稳定产品契约；当轮工单属于动态输入。JSON 字段由 Structured Outputs schema 保证时，不在提示词中重复完整 schema。`reasoning.effort`、`text.verbosity` 和缓存属于调用层配置，应经代表性 eval 决定。

## 7. 普通聊天 / 写作与 API 的区别

```text
请把下面的活动介绍改写成发给社区志愿者的邀请函。目标是让读者知道活动目的、时间地点和报名方式；语气温暖直接。保留所有事实，缺失的信息用方括号占位，不要自行编造。

[活动介绍]
```

这里受众和语气会改变成文结果；不需要工具 schema、缓存或推理参数。

## 8. 其他模型：条件化支持

```text
为目标模型重写这条提示词。保留目标、证据边界、成功标准和失败行为。只有在已提供该模型的官方文档或已验证配置时，才加入平台专用消息角色或参数；否则输出平台无关版本，并标注待核实的集成项。

目标模型：[模型]
原提示词：[内容]
```

不得把 OpenAI API 的字段默认移植到 Claude、Gemini 或本地模型。
