# 决定性澄清问题库

仅当缺失信息会实质改变结果，且错误假设可能造成高返工、高风险或不可逆后果时读取。问题库是候选项，不是 checklist；通常只问一个最小问题，并复用对话和材料中已有信息。

## 选择问题的方法

先判断缺口是否能通过现有材料、仓库、工具或低风险默认值解决。能解决就直接草拟并标注假设。只有以下任一情况成立才提问：

- 授权或副作用边界不清，可能造成外部写入、删除、发布、付费或敏感数据处理；
- 两种合理解释会产生实质不同的交付物，且返工成本高；
- 关键证据、输入或成功标准缺失，继续会使结果不可验证；
- 高风险领域缺少决定行动的事实或人工复核边界。

问题应直接对应分叉点，不询问“还有什么补充”。

## Codex / agent

- “这是只诊断并报告，还是也授权修改文件并运行验证？”
- “允许的改动范围是当前模块，还是包含公共接口和依赖升级？”
- “这项操作只针对本地/测试环境，还是明确授权影响生产环境？”
- “成功以哪些现有测试、可观察行为或兼容性约束为准？”
- “遇到必须扩展范围、执行外部写入或破坏性操作时，应停止并报告，还是另有授权流程？”

能从仓库规则、测试或用户已给出的验收标准获得答案时不要再问。

## OpenAI API

- “这是长期产品级 developer 指令，还是一次性 user 任务？”
- “调用方需要自由文本，还是必须由 Structured Outputs / 工具 schema 消费？”
- “优化目标优先级是什么：任务成功率、延迟、成本还是输出详略？”
- “是否有代表性失败样例和 eval，可用于比较 prompt 或 reasoning 配置？”
- “多轮目标和假设是否稳定到适合保留先前上下文，还是应从当前状态重新开始？”

不要在尚未确定 API 环境时询问具体 OpenAI 参数；也不要把参数选择伪装成提示词内容。

## 普通聊天与写作

- “这段内容主要给谁看，读完希望对方做什么？”
- “必须保留哪些事实、术语或语气特征？”
- “交付物是可直接发送的成稿，还是供继续编辑的草案？”

若答案只会轻微改变措辞，采用常见默认并给草案。只有受众、目的或事实边界会显著改变内容时才问。

## 分析与研究

- “需要支持的具体决策是什么？”
- “结论只能依据提供材料，还是允许检索外部一手来源？”
- “哪些时间边界、地区或样本范围决定结论是否有效？”
- “证据不足时，应列出缺口并停止，还是允许在明确假设下给暂定结论？”

输出格式通常不是首要问题；除非下游系统必须消费固定字段，否则先保证证据和决策边界。

## 高风险任务

- “这项输出用于信息整理、方案比较，还是将直接驱动现实行动？”
- “谁负责最终复核或批准，输出中必须提供哪些证据？”
- “缺少哪项事实会改变行动建议？”
- “哪些动作必须明确禁止，哪些情况必须停止并转交人工？”

不要通过虚构专家角色提升可信度。把来源范围、不确定性、验证动作和人工复核责任写清楚。

## 提示词诊断

- “这条提示词运行在哪个平台和调用方式中？”——仅当平台差异会影响修改。
- “最需要修复的可观察失败是什么？”——用户尚未给出失败样例时。
- “这是单次使用，还是需要长期稳定、可评测的产品契约？”——决定是否需要版本化和 eval。
- “哪些输出字段或行为是下游不可变契约？”——决定必要的输出约束。

若用户已经提供原提示词、失败输出和目标行为，直接诊断和重写，不再进行访谈。

## 提问后的交付

获得决定性答案后，生成完整、干净的当前提示词。未回答但低影响的细节使用最小合理假设；不要继续第二轮机械补齐角色、受众、格式、示例或数量。
