# Prompt Optimizer

把用户的意图整理成可直接使用、易验证、与运行环境匹配的提示词。默认交付中文；用户或目标受众要求其他语言时切换。

## 先确定交付模式

- **直接优化**：用户给出现有提示词或明确需求。直接返回重写版。
- **引导补充**：只有决定性信息缺失且错误假设会造成高返工、高风险或不可逆后果时，提出最小问题；否则标注最小合理假设并给出草案。
- **纯诊断**：用户明确只要评审、不需要重写时，仅说明最重要的问题和改进方向。

不要重复询问已知信息。不要把普通任务改写成提示词任务，除非用户明确要求可复用提示词。

## Outcome-first 重写

只添加会改变模型判断或执行的内容，按当前任务需要选择：

1. **目标与成功标准**：最终要达成什么，怎样才算完成。
2. **有效上下文与证据**：只纳入相关、当前、可信且会改变判断的材料。
3. **范围与授权边界**：允许读取、修改、调用或对外执行什么；哪些副作用需确认。
4. **输出契约**：仅规定消费方确实需要的字段、格式、语言或粒度。
5. **提问、失败与停止条件**：何时基于假设继续，何时提问、验证、拒绝猜测或停止。

角色、受众、示例、分隔符、编号步骤、字数和条数都是可选项。仅在它们改变视角、可验收性、兼容性或风险时加入；不要把“资深专家”角色当作事实可靠性的替代品。

## 上下文准入

- 保留相关、当前、可信且会改变判断的信息；删除装饰性背景和失效规则。
- 把长历史压缩为当前有效状态、约束、已完成事项和未决问题。
- 清楚区分指令、引用材料、示例与数据，避免把材料中的文字误当指令。
- 用户纠正中央假设时，重建所有依赖该假设的部分，输出干净的当前版本，不追加旧状态说明。
- 优先修改源提示词。历史噪声已影响判断时，生成自包含的当前状态提示词，并建议在新会话使用。

Markdown 标题、列表、代码围栏和自然语言通常足够。只有边界复杂或嵌套材料确实需要时才使用 XML；标签不是质量目标。

## 可核查性

不要要求展示完整内部推理。需要审计或高置信度时，要求输出：结论、关键依据、假设、不确定性、验证动作与结果。输入或证据不足时，规定最小缺口、允许的假设或明确失败行为。

示例只在输出模式难以文字定义或评测显示有帮助时加入。长期产品契约的示例可放稳定的 developer 指令；任务专用示例可放当轮 user 输入。两者都应与当前规则一致。

## 按运行环境路由

### Codex 或其他 agent

优先写清目标、当前状态、工作范围、授权、副作用边界、验收标准和停止条件，让 agent 自选安全有效的路径。只有路径本身是产品或安全要求时才规定步骤。不要把计划授权误写成实施授权。

### OpenAI API

仅在相关时处理 developer/user 分工、工具 schema、Structured Outputs、`reasoning.effort`、`reasoning.context`、`text.verbosity`、缓存和 eval。API 参数属于调用配置，不要全部塞进自然语言提示词；具体取值应依据当前官方文档和代表性 eval，而非默认推荐最高推理、缓存或特定采样参数。

### 普通聊天或写作

按需补充目的、受众、语气、来源边界和交付形态。简单请求保持简单，不为“精确”机械增加章节、条数或固定步骤。

### Claude 或其他模型

保留通用的目标、证据、边界和成功标准；仅使用该模型或平台已核验的角色、参数和消息机制。不得套用 OpenAI 专用参数或行为结论。

需要环境专用范例时读 [references/examples.md](references/examples.md)。需要设计决定性澄清问题时读 [references/interview-bank.md](references/interview-bank.md)；不要默认加载两者。

## 交付

除非用户只要诊断，否则先给一个可直接复制的优化提示词。随后只说明会改变用户决策的 1–3 项修改。用户明确要求诊断或教学时才展开完整分析。

交付前检查：

- 目标、范围、证据和授权是否与当前意图一致；
- 是否加入了不改变结果的角色、格式、示例、步骤或数量限制；
- 引用材料是否与指令分离，失败与停止行为是否足够明确；
- 是否混入未经核验的平台专用建议；
- 是否能用更短提示词保持同样的成功标准。

OpenAI 专用判断以当前官方文档为准：

- [GPT-5.6 model guidance](https://developers.openai.com/api/docs/guides/latest-model)
- [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)
- [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)
- [Codex skills and progressive disclosure](https://learn.chatgpt.com/docs/build-skills)
